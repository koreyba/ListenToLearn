# Requirements & Problem Understanding

## Problem Statement

После подключения Google Cloudflare Access закрывает весь Worker hostname. Новый посетитель не может открыть даже главную страницу и тренажёр, хотя ему нужно дать безопасно попробовать продукт.

При этом аккаунтный режим уже должен оставаться per-user: прогресс, пользовательские фразы, сохранённые примеры и DeepL-ключ сохраняются только для подтверждённого Google-аккаунта. Гостевой эксперимент не должен создавать или изменять эти данные.

## Goals & Objectives

### Goals

- Открыть для анонимного посетителя главную страницу, тренажёр и безопасные публичные источники примеров.
- Дать гостю полноценную пробу: менять статусы фраз, добавлять свои фразы, сохранять примеры и проходить локальный тренажёр.
- Хранить гостевое состояние только в browser `localStorage`, отдельно от аккаунтных ключей и D1.
- Сохранить Google-вход и серверное per-user-хранение без изменения правил изоляции.
- Оставить Integrations, DeepL и пользовательские API защищёнными авторизацией.
- Не добавлять новые Cloudflare-платные ресурсы и не писать гостевые данные в D1.

### Non-goals

- Автоматический перенос гостевого прогресса в аккаунт после Google-входа.
- Серверные anonymous-сессии, временные D1-строки, cleanup-задачи или guest cookies.
- Использование общего DeepL-ключа для гостей.
- Изменение модели команд, ролей или совместных библиотек.

## User Stories & Use Cases

- Как новый посетитель, я хочу открыть `/` без Google-входа и увидеть, как устроена библиотека.
- Как гость, я хочу открыть фразу в тренажёре, менять локальный прогресс и добавлять свои фразы, не влияя на аккаунты.
- Как гость, я хочу сохранять примеры локально, чтобы попробовать основной сценарий.
- Как гость, я хочу видеть понятный призыв войти через Google для Integrations и серверного сохранения.
- Как пользователь Google, я хочу получить прежнюю личную библиотеку и DeepL-ключ после входа, без появления гостевых данных.
- Как пользователь, я хочу очистить пробный guest state одним действием.

### Edge cases

- Гость отправляет прямой `POST/PATCH/DELETE` в пользовательский API: запрос не должен менять D1 и должен получить `401` либо Access redirect.
- Гость открывает `/api/me`, `/api/phrases`, `/api/examples`, `/api/translate` напрямую: это не должно открывать аккаунтные данные.
- У гостя отключён или недоступен `localStorage`: приложение должно продолжить работу в памяти и показать предупреждение, но не падать.
- Пользователь выходит из Google и тот же браузер открывает приложение: guest state и аккаунтный state не должны смешиваться.
- У гостя нет DeepL-ключа: перевод остаётся необязательным и не блокирует локальное добавление/продвижение фразы.

## Success Criteria

- В чистом браузере `GET /` и `GET /trainer.html` отдают приложение без Cloudflare Access redirect.
- Публичные Tatoeba endpoints работают без identity и не выполняют D1-записей.
- `/integrations`, `/login`, `/api/me`, `/api/phrases`, `/api/examples`, `/api/translate` и `/api/integrations` остаются защищёнными.
- В guest mode изменение статусов, добавление фраз и сохранение/удаление примеров изменяют только guest `localStorage`.
- После guest действий количество записей в D1 и данные любого аккаунта не меняются.
- После Google-входа используются существующие user-scoped API и namespaced trainer storage; guest state автоматически не импортируется.
- Worker проверяет Access JWT на защищённых запросах и пропускает без JWT только явно разрешённые публичные маршруты.
- `npm run lint`, typecheck, build и тесты проходят; live smoke подтверждает public root/trainer, protected API и Access redirect.
- Реализация не требует D1 migration, KV, R2, Durable Objects, Queues или платного плана.

## Constraints & Assumptions

- Feature name и ветка: `public-guest-local-mode` / `feature-public-guest-local-mode`.
- Рабочая среда: Cloudflare Worker + Static Assets + D1 + Cloudflare Access Free.
- `localStorage` выбран вместо `sessionStorage`, чтобы гостевой сценарий сохранялся между главной и тренажёром и не исчезал при обычной перезагрузке. Это browser-only проба, а не аккаунтное сохранение.
- Для строгого удаления server-side данных достаточно не вызывать пользовательские mutation API из guest UI; сервер всё равно fail-closed.
- Публичные Tatoeba proxy endpoints не используют D1 и не имеют пользовательских записей.
- Для входа будет отдельный protected `/login` path; после успешного Access login Worker возвращает пользователя на публичную главную с account bootstrap marker.
- Гостевые и аккаунтные данные не объединяются автоматически; явный импорт можно спроектировать отдельно.

## Questions & Open Items

- Продуктовое решение по lifetime гостя принято как `localStorage` + явная очистка.
- Автоматический guest-to-account merge явно отложен.
- Операционный rollout Access должен сначала сохранить текущие Google audiences и только после smoke сузить host-wide application до protected paths.
